# 🎤 ระบบโรงเรียนสอนร้องเพลง "ครูแอร์" — Design Specification v2

> **Web Application + LINE Official Account (LINE OA) + Payment Gateway (KBank / บัตรเครดิต)**
> อ้างอิงจาก One-Page Brief (Infographic) ของครูแอร์ · Prototype ที่กดได้: `docs/prototype.html` · Web App mockup: `docs/web-app.html`

## ⚠️ หลักการสำคัญ (Web-First — อัปเดตล่าสุด)

> **เว็บแอปพลิเคชัน (เว็บไซต์) คือระบบหลัก ส่วน LINE OA เป็นฟีเจอร์เสริม**

- นักเรียนสมัคร/เข้าสู่ระบบผ่าน **เว็บไซต์** เป็นหลัก (อีเมล/เบอร์โทร + รหัสผ่าน) — LINE Login เป็นเพียงทางเลือกเสริม
- ทุกฟีเจอร์ทำงานครบในเว็บ: หน้าแรก/แพ็กเกจ/วิธีเรียน/รีวิว/ติดต่อ (หน้าเว็บไซต์ประชาสัมพันธ์) + Student Portal + Admin Dashboard
- **LINE OA (เสริม):** แจ้งเตือนผ่าน LINE Push (เตือนนัด 1 วัน, ใบเสร็จ), Rich Menu ลิงก์กลับเข้าสู่หน้าเว็บ (LIFF), และทางลัดสำหรับนักเรียนที่ใช้ LINE เป็นหลัก
- ฐานข้อมูล/ระบบหลังบ้านเป็นชุดเดียว — LINE และเว็บอ้างอิงข้อมูลเดียวกัน (จองจากที่ไหนก็เห็นพร้อมกัน)
- Mockup เว็บไซต์หลัก: `docs/web-app.html` (เปิดด้วยหน้า Landing → สมัคร/เข้าสู่ระบบ → Portal)

## 1. ภาพรวม & เป้าหมายของระบบ

ระบบบริหารจัดการโรงเรียนสอนร้องเพลงของครูแอร์ ครอบคลุมวงจรชีวิตนักเรียนครบวงจร:

```
สมัครสมาชิก (LINE) → ซื้อแพ็กเกจ (วอเชอร์ + ชำระเงิน) → จองเวลาเรียน
→ แจ้งเตือน 1 วัน + คอนเฟิร์มนัด → เข้าเรียน → บันทึกการสอน + หักชั่วโมง
```

**เป้าหมาย (จาก Brief):**
1. **จองเวลาเรียน** — นักเรียนเลือกวัน/เวลาเรียนได้เองผ่าน LINE หรือเว็บ
2. **ซื้อแพ็กเกจ** — เลือกแพ็กเกจตามจำนวนชั่วโมง (10 / 20 / 30 ชม.)
3. **ใช้วอเชอร์ส่วนลด** — ลดราคาในการซื้อแพ็กเกจ
4. **แจ้งเตือน & คอนเฟิร์ม** — เตือนล่วงหน้า 1 วัน + ให้นักเรียนคอนเฟิร์มนัดหมาย
5. **เชื่อมต่อ LINE OA** — ใช้งานผ่าน LINE ได้สะดวก รวดเร็ว

## 2. สถาปัตยกรรมระบบ (Web App + LINE OA + Payment Gateway)

```

        │        Rich Menu / Flex)         │

┌──────────────────────────────────────────────────────────────────┐
│                    WEB APPLICATION (Frontend + Backend)          │

└──────────────────────────────────────────────────────────────────┘
```

**แนวคิดหลัก (Design Decisions):**
- **ช่องทางหลักของนักเรียน = เว็บไซต์** (สมัคร/ซื้อ/จอง/คอนเฟิร์ม ผ่านหน้าเว็บครบทุกอย่าง) — **LINE OA เป็นฟีเจอร์เสริม** สำหรับแจ้งเตือน Push และเมนูลัด (LIFF ลิงก์กลับเว็บ)
- **Web App ประกอบด้วย:** (1) หน้าเว็บไซต์ประชาสัมพันธ์ (Landing: hero/แพ็กเกจ/วิธีเรียน/รีวิว/ติดต่อ) (2) **Student Portal** (3) **Admin Dashboard** (ครูแอร์/แอดมิน: ตารางสอน, ตรวจสอบยอด, ออกวอเชอร์, อนุมัติเลื่อนนัด, บันทึกการสอน)
- **Auth:** สมัคร/เข้าสู่ระบบด้วยอีเมลหรือเบอร์โทร + รหัสผ่าน (hash ปลอดภัย) — LINE Login เป็นทางเลือกเสริมและใช้ผูกบัญชีเพื่อรับ Push
- **ชำระเงินอัตโนมัติ:** จ่ายสำเร็จผ่าน Webhook → เพิ่มชั่วโมงเข้าบัญชีทันที
- **หักชั่วโมงเมื่อเรียนจริง:** การจองไม่หักชั่วโมง — หัก 1 ชม. ต่อคลาส **เมื่อครูแอร์บันทึกการสอนหลังจบคลาส** (ตามเงื่อนไขแพ็กเกจ)

## 4. Functional Requirements (ขยายความจาก Brief)

### 4.1 การสมัครสมาชิก (เว็บไซต์เป็นหลัก · LINE เป็นทางเลือก)

1. นักเรียนสมัครผ่าน **หน้าเว็บไซต์** (หรือหน้า LIFF ใน LINE — เป็นทางเลือกเสริม)
2. **เข้าสู่ระบบด้วยอีเมล/เบอร์โทร + รหัสผ่าน** (เก็บ hash + session) — หรือใช้ **LINE Login** เป็นทางเลือก และสามารถผูกบัญชี LINE ภายหลังเพื่อรับการแจ้งเตือน Push
3. กรอกฟอร์มสมัครสมาชิก (หน้าเว็บหรือ LIFF):

| # | ฟิลด์ | ประเภท | หมายเหตุ |
|---|---|---|---|
| 1 | ชื่อจริง | ข้อความ (required) | ใช้ในใบเสร็จ/สัญญา |
| 2 | ชื่อเล่น | ข้อความ (required) | ใช้เรียกในแชท |
| 3 | อายุ | ตัวเลข (required) | |
| 4 | ระดับการศึกษา | dropdown (required) | ม.ต้น / ม.ปลาย / ปวช.-ปวส. / ป.ตรี / ป.โท+ / อื่นๆ |
| 5 | แนวเพลงที่ชอบ | multi-select (required) | Pop, Ballad, Rock, R&B, Hip-Hop, ลูกทุ่ง, Jazz, อื่นๆ |
| 6 | เหตุผลของการอยากเรียนร้องเพลง | textarea (required) | ใช้ประกอบการออกแบบคอร์ส |

4. ✅ ยอมรับ PDPA → สร้างโปรไฟล์นักเรียน → ข้อความต้อนรับ + แนะนำขั้นตอนถัดไป

### 4.2 แพ็กเกจที่เปิดให้บริการ

| แพ็กเกจ | ชั่วโมง | ราคา | เฉลี่ย/ชม. | Badge |
|---|---|---|---|---|
| 🎵 Package 10 ชั่วโมง | 10 ชม. | 22,000 บาท | 2,200 บาท | — |
| 🎶 Package 20 ชั่วโมง | 20 ชม. | 40,000 บาท | 2,000 บาท | 👑 ยอดนิยม |
| 🎤 Package 30 ชั่วโมง | 30 ชม. | 56,000 บาท | 1,867 บาท | คุ้มสุด |

**เงื่อนไขแพ็กเกจ (จาก Brief — แสดงในหน้าแพ็กเกจทุกครั้ง):**
- 📌 **นับชั่วโมงเมื่อเข้ารับจริง** — 1 ชั่วโมง/ครั้ง (จองแล้วยังไม่หัก)
- ⏳ **แพ็กเกจมีอายุ 6 เดือน** นับจากวันที่ซื้อ (แจ้งเตือนก่อนหมดอายุ 30 / 7 / 1 วัน)
- 🚫 **ไม่สามารถโอนหรือคืนเงินได้**
- 🎤 **ใช้ได้เฉพาะคอร์สของครูแอร์เท่านั้น**

### 4.3 การซื้อแพ็กเกจ & การชำระเงิน (6 ขั้นตอน)

```
1. เลือกแพ็กเกจ → 2. ใส่วอเชอร์ส่วนลด (ถ้ามี) → 3. ระบบคำนวณยอดส่วนลด
→ 4. เลือกช่องทางชำระเงิน → 5. ชำระเงิน → 6. ชำระเงินสำเร็จ เพิ่มชั่วโมงเข้าบัญชี
```

**วอเชอร์ส่วนลด:**
- กรอกรหัสตอนขั้นสรุปซื้อ ตรวจสอบแบบ real-time
- รองรับ: ลดเป็นบาท / ลดเป็น % (มีเพดานสูงสุดได้) / ใช้ครั้งเดียวหรือหลายครั้ง / จำกัดบางแพ็กเกจ / วันหมดอายุ
- แอดมินสร้าง/ปิดวอเชอร์ได้จาก Dashboard

**ช่องทางชำระเงิน (Payment Gateway):**
| ช่องทาง | รายละเอียด |
|---|---|
| 💳 บัตรเครดิต / เดบิต | Visa, Mastercard, JCB ผ่าน KBank Gateway (รองรับ 3-D Secure) |
| 🏦 โอนเงินผ่าน KBank | K+ / e-Payment ผ่าน KBank Payment Gateway — ระบบตรวจสอบยอดอัตโนมัติ |

**หลักการสำคัญ:**
- Webhook จากเกตเวย์ (idempotent — ป้องกันจ่ายซ้ำ) → เพิ่มชั่วโมงเข้าบัญชีอัตโนมัติ + ส่งใบเสร็จ PDF ผ่าน LINE
- จ่ายไม่สำเร็จ/หมดเวลา → ยกเลิกอัตโนมัติ + ปุ่ม "ลองอีกครั้ง"
- ทุกธุรกรรมมีสถานะชัดเจน: `PENDING → SUCCESS / FAILED / EXPIRED`

### 4.4 การจองเวลาเรียน

1. นักเรียนเลือก **วัน** (ปฏิทิน 2 สัปดาห์ถัดไป, วันปิด = สีเทา) → ระบบแสดง **สล็อตว่าง** (60 นาที/สล็อต)
2. เลือกสล็อต → หน้าสรุป → ยืนยัน
3. **จองสำเร็จ → ระบบล็อกสล็อต (Hold) ไว้ทันที** เพื่อกันซ้ำซ้อน
4. แจ้งเตือนครูแอร์ก่อนเริ่มเรียน **1 ชั่วโมง** (ตาม Brief "ระบบพักที่ว่าง ล่วงหน้า 1 ชั่วโมง" — หมายถึงการ์ดแจ้งเตือนให้ครูแอร์เตรียมตัว หรือตามที่ตกลงกัน — ดู Open Questions)
5. สถานะนัด: `BOOKED` → `AWAITING_CONFIRM` → `CONFIRMED` → `COMPLETED` / `MOVED` / `CANCELLED` / `NO_SHOW`

### 4.5 แจ้งเตือนล่วงหน้า 1 วัน + คอนเฟิร์มนัดหมาย (หัวใจของระบบ)

- **เวลา:** Job Scheduler ส่ง LINE Push **24 ชม. ก่อนเริ่มเรียน** พร้อม Flex Message + ปุ่มกด:

| ปุ่ม | พฤติกรรม |
|---|---|
| ✅ **ยืนยันมาเรียน** | สถานะ → `CONFIRMED`, ส่งข้อความยืนยันกลับ ("แล้วพบกันนะคะ") |
| 🔁 **ขอเลื่อนนัด** | เปิดฟอร์มเลือกวัน/เวลาใหม่ → สถานะ `MOVE_REQUESTED` → **รอแอดมินตรวจสอบและยืนยันเวลาใหม่** → ระบบอัปเดตสถานะ + แจ้งเตือนผ่าน LINE |
| ❌ **ยกเลิกนัด** | กรอกเหตุผล → `CANCELLED` (ตามนโยบายการยกเลิก) |

- **ไม่ตอบกลับ** ภายใน 6 ชม. ก่อนเรียน → ทวงถาม 1 ครั้ง → ยังไม่ตอบ → แจ้งเตือนครูแอร์ใน Dashboard (รายการ escalate)

### 4.6 บันทึกการสอน & หักชั่วโมง (นับชั่วโมงเมื่อเข้ารับจริง)

- หลังจบคลาส **ครูแอร์กด "บันทึกการสอน"** ใน Admin (หรือหลัง 1 ชม. ระบบถามยืนยัน)
- ระบบ **หักชั่วโมง 1 ชม.** จากแพ็กเกจ (ตัดแพ็กเกจที่หมดอายุก่อน = FIFO) + บันทึกประวัติการเรียน (วัน/เวลา/บทเรียน/บันทึกครู)
- กรณีนักเรียนไม่มา (no-show) ตามเวลาที่จองและยืนยัน → ระบบให้ครูแอร์กด `NO_SHOW` → หักชั่วโมงตามนโยบาย

### 4.7 แอดมิน / ครูแอร์ (Admin Dashboard)

- **ครูแอร์:** ตารางสอนรายวัน/รายสัปดาห์, ดูข้อมูลนักเรียน, บันทึกผลการสอน, เปิด-ปิดสล็อต
- **แอดมิน:** จัดการนักเรียน / แพ็กเกจ / วอเชอร์ / การจอง, ตรวจสอบการชำระเงิน, **อนุมัติ/ปฏิเสธคำขอเลื่อนนัด**, รายงานสรุปยอดขายและสถิติการเรียน (รายเดือน, แยกแพ็กเกจ, แยกช่องทางจ่าย)

## 5. UX/UI Design — LINE OA (ฟีเจอร์เสริมของระบบเว็บ)

### 5.1 Rich Menu 6 ปุ่ม (ตาม Brief)

```
┌──────────────┬──────────────┬──────────────┐
│  📅 จองเวลา  │  🎟️ แพ็กเกจ  │  📖 ประวัติ   │
│  เรียน       │  ของฉัน      │  การเรียน    │
├──────────────┼──────────────┼──────────────┤
│  👤 โปรไฟล์   │  🛒 ซื้อ      │  💬 ติดต่อ    │
│              │  แพ็กเกจ     │  ครูแอร์     │
└──────────────┴──────────────┴──────────────┘
```

| ปุ่ม | Action | ปลายทาง |
|---|---|---|
| จองเวลาเรียน | `uri: LIFF` | ปฏิทิน + สล็อต |
| แพ็กเกจของฉัน | `postback: MY_HOURS` | Flex สรุปชั่วโมงคงเหลือ/หมดอายุ |
| ประวัติการเรียน | `postback: MY_HISTORY` | Flex รายการคลาสที่เรียนแล้ว |
| โปรไฟล์ | `uri: LIFF` | ดู/แก้ไขข้อมูลสมัคร |
| ซื้อแพ็กเกจ | `uri: LIFF` | เลือกแพ็กเกจ + วอเชอร์ + ชำระ |
| ติดต่อครูแอร์ | `postback: CONTACT` | ข้อมูลติดต่อ/เวลาทำการ |

### 5.2 Flow หลักบน LINE (ดู Prototype `docs/prototype.html` ได้เลย)

- **Flow A — สมัคร:** ต้อนรับ → ปุ่มสมัคร → LIFF ฟอร์ม 6 ฟิลด์ → สำเร็จ
- **Flow B — ซื้อแพ็กเกจ:** เลือกแพ็กเกจ → วอเชอร์ → สรุปยอด → เลือกช่องทางจ่าย (บัตร/KBank) → สำเร็จ + เพิ่มชั่วโมง
- **Flow C — จองเรียน:** เลือกวัน → เลือกสล็อต → ยืนยัน → ล็อกสล็อต (ยังไม่หักชั่วโมง)
- **Flow D — เตือน 1 วัน:** Flex Message + ปุ่ม ยืนยัน / เลื่อน / ยกเลิก
- **Flow E — เลื่อนนัด:** เลือกวันเวลาใหม่ → `รอแอดมินอนุมัติ` → แจ้งผลผ่าน LINE
- **Flow F — ชั่วโมงคงเหลือ / ประวัติ / โปรไฟล์**

## 7. โครงสร้างข้อมูล (Data Model + สถานะ)

```
students ─┬─< purchases >─── packages        vouchers
          │      │                                ▲
          │      └─< payments (PENDING/SUCCESS/   │ (bind กับ purchase)
          │              FAILED/EXPIRED)          │
          │      └─< hour_ledger (+/- ทุกธุรกรรม)  │
          │
          └─< bookings >─── lesson_slots (open/booked/closed)
                │
                └─< booking_events (ยืนยัน/เลื่อน/ยกเลิก/บันทึกการสอน + timestamp)

- students:  line_user_id, real_name, nickname, age, education, genres[], reason, consent_pdpa, created_at
- packages:  name, hours, price, active, sort
- purchases: student_id, package_id, voucher_id, gross, discount, net, status, hours_added, expires_at (=ซื้อ+6 เดือน)
- payments:  purchase_id, method (card/kbank), gateway_ref, status, paid_at, raw_webhook
- hour_ledger: student_id, purchase_id, booking_id, delta (+/-), reason, created_at  ← ใช้คำนวณชั่วโมงคงเหลือแบบ audit
- lesson_slots: teacher_id, start_at, end_at, status (open/booked/closed)
- bookings:  student_id, slot_id, status, hold_at, confirmed_at, moved_to_id, cancel_reason, completed_at, teacher_note
- notifications: type (reminder/nudge/expiry/receipt), target, payload, sent_at, replied_at
```

**สถานะนัด (Booking State Machine):**
```
BOOKED ──(24 ชม.ก่อนเรียน: ส่งเตือน)──> AWAITING_CONFIRM ──กดยืนยัน──> CONFIRMED
   │                                        │                       │
   └─ยกเลิก──> CANCELLED                    └─ไม่ตอบ──> nudge ──> escalate ครูแอร์
                                           เลื่อนนัด: MOVE_REQUESTED ──แอดมินอนุมัติ──> BOOKED (สล็อตใหม่)
                                                                      └─ปฏิเสธ──> AWAITING_CONFIRM
CONFIRMED ──เรียนจบ──> COMPLETED (+หัก 1 ชม. +ประวัติ) · ──ไม่มา──> NO_SHOW (หักตามนโยบาย)
```

## 10. API Design (ภาพรวม Endpoints)

```
POST /api/webhook/line        ← LINE Messaging API (ข้อความ/Postback)
POST /api/webhook/kbank       ← KBank Gateway (ผลการชำระเงิน, idempotent)

POST   /api/auth/line         LINE Login → สร้าง/ดึง token
POST   /api/students          สมัครสมาชิก (ข้อมูล 6 ฟิลด์ + consent)
GET    /api/students/me       โปรไฟล์ + ชั่วโมงคงเหลือ (จาก hour_ledger)

GET    /api/packages          รายการแพ็กเกจ
POST   /api/purchases         สร้างคำสั่งซื้อ (package + voucher)
POST   /api/purchases/:id/pay เริ่มชำระ (card → redirect 3DS / kbank → QR)
GET    /api/purchases/:id     สถานะ + ใบเสร็จ

GET    /api/slots?from&to     สล็อตว่าง
POST   /api/bookings          จอง (ล็อกสล็อต, atomic)
POST   /api/bookings/:id/confirm    ยืนยันนัด (จากปุ่ม LINE)
POST   /api/bookings/:id/move       ขอเลื่อน (รอแอดมิน)

GET    /api/admin/bookings?status=MOVE_REQUESTED
POST   /api/admin/bookings/:id/approve-move
POST   /api/admin/vouchers    สร้างวอเชอร์
GET    /api/admin/reports/sales?month=...
```

## 11. Payment Integration (KBank Gateway) — รายละเอียด

1. **เริ่มชำระ:** Backend สร้างคำสั่งซื้อ `PENDING` → ขอ token/QR จาก KBank
   - บัตร: redirect นักเรียนไปหน้า 3-D Secure → กลับมา callback
   - K+: แสดง QR/ลิงก์ → นักเรียนยืนยันในแอป K PLUS
2. **ผลการชำระ:** KBank ส่ง Webhook → ระบบตรวจสอบ signature + ตรวจ `idempotency_key` (กันจ่ายซ้ำ) → อัปเดต `SUCCESS`
3. **เพิ่มชั่วโมง:** Insert `hour_ledger +N` + `purchases.hours_added` + `expires_at = now + 6 เดือน` **ใน transaction เดียว**
4. **แจ้งผล:** LINE Push สรุป + ใบเสร็จ PDF
5. **ล้มเหลว/หมดเวลา:** `FAILED`/`EXPIRED` → ปุ่ม "ลองอีกครั้ง" (สร้าง purchase ใหม่)
6. **Reconciliation:** จ็อบกลางคืนเทียบยอด Webhook vs ใบแจ้งยอด KBank

> ⚠️ ขอรายละเอียด API จาก KBank (KPayment / ผ่านตัวกลาง Omise-2C2P) เพื่อกำหนดฟอร์แมต Webhook และช่องทางบัตรที่รองรับจริง

## 12. Roadmap

## 13. คำถามเปิด (ต้องตกลงกับครูแอร์ก่อนเริ่มพัฒนา)

1. **"ระบบพักที่ว่าง ล่วงหน้า 1 ชั่วโมง"** — หมายถึงแจ้งเตือนครูแอร์ก่อนคลาส 1 ชม. หรือระบบปลดล็อกสล็อตหากยังไม่ยืนยัน? (แนะนำ: แจ้งเตือนครู 1 ชม. + ยังล็อกสล็อตไว้)
2. **นโยบายยกเลิก/เลื่อน** — ยกเลิกก่อน 24 ชม. ไม่เสียชั่วโมง? เลื่อนได้กี่ครั้ง/เดือน?
3. **No-show** — นักเรียนยืนยันแล้วแต่ไม่มา → หักชั่วโมงทันทีใช่ไหม?
4. **การเลื่อนนัด** — ต้องรอแอดมินอนุมัติทุกครั้ง (ตาม Brief) หรืออนุมัติอัตโนมัติถ้าสล็อตใหม่ว่าง?
5. **KBank gateway** — ใช้ KPayment API โดยตรง หรือผ่าน Omise/2C2P? บัตรรองรับยี่ห้อใดบ้าง?
6. **ใบกำกับภาษี** — ครูแอร์มีนิติบุคคล/เลขผู้เสียภาษีหรือไม่?
7. **สล็อตมาตรฐาน** — 60 นาที/สล็อต ใช่ไหม? มีวันหยุด/เวลาพักประจำไหม?
8. **แพ็กเกจหมดอายุแล้วยังเหลือชม.** — ต่ออายุ (ต่อเงิน) หรือตัดทิ้ง? ต้องกำหนด workflow
